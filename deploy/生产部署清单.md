## 2. 标准流程

### §1 本机构建镜像（本机执行）

前置：本机 Docker Desktop 在运行（实测 29.8.0 / linux/amd64 —— 与生产、测试服务器架构一致，产物可直接搬运）。

```powershell
cd d:\GoLang\colorAI
docker compose build
```

预期：`colorai-go-backend:latest` 与 `colorai-agent:latest` 构建成功（镜像名由 compose 的 `image:` 字段固定，天然正确）。

说明：
- 首次构建慢（拉 `golang:1.25-alpine` / `python:3.11-slim` 基础镜像 + 清华源装 langchain 全家桶）；之后改代码重构走缓存，很快
- 改了 `requirements.txt`：agent 的依赖层缓存自动失效重装，无额外操作
- 两份 `.env` **不参与构建**（运行时由 compose 的 `env_file` 注入），构建过程不涉及任何密钥

只构建单个服务（可选，更快）：

```powershell
docker compose build go-backend    # 只改 Go 时
docker compose build agent         # 只改 agent / requirements.txt 时
```

### §2 导出镜像包（本机执行，推荐 Git Bash）

```bash
cd /d/GoLang/colorAI
docker save colorai-go-backend:latest colorai-agent:latest | gzip > colorai-images.tar.gz
ls -lh colorai-images.tar.gz
```

> ⚠️ **不要在 PowerShell 里写这条管道** —— PS 5.1 的管道会损坏二进制流，且系统没有 `gzip`。
> 纯 PowerShell 等价做法：
> ```powershell
> docker save -o colorai-images.tar colorai-go-backend:latest colorai-agent:latest
> # 压缩另做：Git Bash 里 `gzip colorai-images.tar`，或 7-Zip 压成 `.gz`
> ```

- 只改了一个服务时只导一个：`docker save colorai-agent:latest | gzip > colorai-agent.tar.gz`
- 本机在线构建的 agent 镜像约 824MB（比旧离线构建版 655MB 大，差在 gcc 等构建依赖），导出包相应大一些；功能无差异
- 导出产物不在 `.gitignore` 覆盖范围内，**别误提交**版本库；传完即可删

### §2.5（可选，建议）先到测试机预发验证

保留这道保险：先把包 load 到测试机，在 `http://wzx.glaty.cn:8080` 过一遍核心功能，通过后再搬生产。

```bash
# 本机（Git Bash）：上传到测试机
scp colorai-images.tar.gz root@118.31.10.161:/root/tmp/
```

```bash
# 测试机：加载并启动（镜像已构建好：不再叠加 offline compose，也不再 --build）
cd /root/tmp
gunzip -c colorai-images.tar.gz | docker load
docker images | grep colorai
cd /home/www/project/colorAI
docker-compose up -d --no-build
docker-compose ps
curl -s http://127.0.0.1:3001/api/health    # {"message":"ok","success":true}
```

> 备注：测试机预览页面的前端是上次上传的版本（见 §4 备注）；本节只校验后端镜像。

### §3 搬运镜像到生产（本机 → 生产机）

```bash
# ① 本机（Git Bash）：上传到生产机（方式任选：scp / 宝塔文件管理）
scp colorai-images.tar.gz root@<生产IP>:/root/tmp/
```

```bash
# ② 生产机：先备份「当前版本」（回滚用），再加载新镜像
cd /root/tmp
docker save colorai-go-backend:latest colorai-agent:latest | gzip > colorai-images-prev.tar.gz
gunzip -c colorai-images.tar.gz | docker load
docker images | grep colorai          # 两个 latest 的创建时间应为刚刚

# ③ 生产机：重启容器（⚠️ --no-build 必须加）
cd /root/project/coloragent
docker-compose up -d --no-build
docker-compose ps
```

说明：
- `--no-build` 的作用：镜像名万一不匹配会**直接报错**，而不是偷偷在现场构建（那要联网装依赖，几分钟起步）
- **只改了 agent 时**可只搬一个镜像：`docker save colorai-agent:latest ...` / `docker load` 同理
- 只改前端时整个 §1~§3 跳过

> ⚠️ 万一 `up` 报 `No such image: sha256:...` + `Continue with the new image? [yN]` 中止（旧容器引用的镜像 ID 已不可解析时的交互保护）—— 先删旧容器再重启：
> ```bash
> docker rm -f colorai-go colorai-agent    # ⚠️ 只删这两个；绝不能碰 colorai-nginx
> docker-compose up -d --no-build
> ```

### §3.5 生产配置文件同步（仅改了 compose / .env 时才做）

日常代码迭代**不需要**这一步。真改了就这么传（单独覆盖对应文件）：

```bash
# 本机（示例：只传 compose；.env 同理）
scp docker-compose.yml root@<生产IP>:/root/project/coloragent/
scp go-backend/.env      root@<生产IP>:/root/project/coloragent/go-backend/.env

# 走了 §2.5 测试机验证的，同一份文件也同步给测试机，否则验证的还是旧配置：
scp docker-compose.yml root@118.31.10.161:/home/www/project/colorAI/
scp go-backend/.env      root@118.31.10.161:/home/www/project/colorAI/go-backend/
```

> ⚠️ 传完后到生产确认 compose 里 `image:` 两行还在（`grep -n image docker-compose.yml`）——**别用旧版文件把它覆盖没了**。
> ⚠️ `agent/.env` 严禁新增代码未声明的键（pydantic `extra_forbidden` 会让服务起不来）。

### §4 更新前端（本机 → 生产）

```powershell
cd d:\GoLang\colorAI\ColorAI
npm run build           # 产物在 dist/（12 个文件）
```

上传二选一：

- **方式 A（推荐，宝塔）**：把 `dist` 里的文件打成 zip → 宝塔面板 → 文件 → 进入 `/www/wwwroot/ai.ququan.net` → 上传 → 在线解压**覆盖**（宝塔操作的文件属主自动为 www）
- **方式 B（命令行）**：

```powershell
# 本机打包
cd d:\GoLang\colorAI\ColorAI
tar -czf dist.tar.gz -C dist .
```

```bash
# 生产机解包覆盖 + 修属主
cd /root/tmp && tar xzf dist.tar.gz -C /www/wwwroot/ai.ququan.net
chown -R www:www /www/wwwroot/ai.ququan.net
```

> 静态文件覆盖即生效，**不需要重启 nginx**。
> 测试机前端若需同步：`upload_dist.py --clean` 后**必须** `docker restart colorai-nginx`（--clean 会换目录 inode，容器挂载"看不到"新文件——已踩过的坑）。

## 3. 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `up` 报 `No such image` + `[yN]` 中止 | 旧容器引用的镜像 ID 已不可解析时的 compose 交互保护 | `docker rm -f colorai-go colorai-agent` 后重新 `up -d --no-build`（见 §3；⚠️ 别误删 colorai-nginx） |
| `docker save` 管道导出报错 / 包损坏 | 在 PowerShell 里跑二进制管道（PS 5.1 会改坏二进制流，系统也没有 gzip） | 改用 Git Bash；或 `docker save -o` 后再单独压缩（见 §2） |
| 生产 go 容器反复重启（Restarting） | 数据库连不上（白名单/地址） | `docker-compose logs --tail=30 go-backend`；把生产机 IP 加入 `8.140.227.153` 宝塔防火墙 + 云安全组（3306/5432/6379） |
| agent 秒退、起不来 | `.env` 有未声明的键 / PG 连不上 | `docker-compose logs agent \| grep -i extra_forbidden`；对照 `app/config.py` 的 Settings |
| 外网打不开、本机 curl 通 | 安全组没放行 | 云控制台 + 宝塔防火墙放行 80/443 |
| 保存宝塔配置报 `duplicate directive` | 模板里已有同名指令 | 删掉**我们那段里**重复的那一行（如 `client_max_body_size` / `gzip`） |
| 传图报 413 | `client_max_body_size` 丢了 | 生产宝塔配置里找回 `client_max_body_size 20m;` |
| 测试机 `--clean` 后页面 403/404 | bind mount inode 陈旧 | `docker restart colorai-nginx` |
| 页面还是旧版本 | PWA / 浏览器缓存 | 硬刷新（Ctrl+Shift+R）；确认 `index.html` 已覆盖且 `sw.js` 未被缓存 |
| 生产 502 | 后端容器没起 / nginx 反代段丢失 | `docker-compose ps`；确认宝塔配置里 `location /api/` 段还在 |
| 生产域名访问到别的页面 | 宝塔上多个站点抢 server_name | 检查 `server_name ai.ququan.net` 唯一 |

## 4. 回滚

**后端**（假设新版有问题）：

```bash
# 用 §3 里备份的 prev 包（须是最近一次成功版本的镜像）
cd /root/tmp
gunzip -c colorai-images-prev.tar.gz | docker load     # 同名 tag 直接覆盖回去
cd /root/project/coloragent
docker-compose up -d --no-build
```

**前端**（覆盖前先备份）：

```bash
# 备份（每次更新前执行一次即可）
tar czf /root/tmp/dist-prev.tar.gz -C /www/wwwroot/ai.ququan.net .
# 回滚
tar xzf /root/tmp/dist-prev.tar.gz -C /www/wwwroot/ai.ququan.net
chown -R www:www /www/wwwroot/ai.ququan.net
```

## 附录 A：从零部署（换服务器 / 灾难重建时用）

1. **生产机前置**：安装 docker + docker-compose；安全组放行 80/443；把生产机 IP 加入数据库 `8.140.227.153` 白名单
2. **搬运镜像**：本机构建 + 导出（见 §1~§2）→ 生产 `gunzip -c colorai-images.tar.gz | docker load`
3. **项目文件**：本机用现成脚本上传（含 compose / go-backend/ / deploy/ 与两份 `.env`；自动排除 `.venv` / data 等重物）：
   ```powershell
   & $PY deploy/upload_backend.py --host <新服务器IP> --remote-dir <目标目录> --backup
   ```
   预期：`✅ 上传完成`、远端两份 `.env` 在位、compose 解析正好 `go-backend` + `agent` 两行
4. **确认 compose 有 `image:` 字段**（否则镜像名对不上）：`grep -n image docker-compose.yml` 应有两行
5. **启动**：`docker-compose up -d --no-build` → `curl http://127.0.0.1:3001/api/health`
6. **前端**：dist 解包到站点目录（`--strip-components=1` 剥掉外层目录）+ `chown -R www:www <目录>`
7. **nginx（宝塔）**：站点 `server {}` 块内加入以下配置段（模板锚点注释 `#SSL-START` / `#REWRITE-START` 等**勿删**）：

   ```nginx
   client_max_body_size 20m;
   gzip on;
   gzip_vary on;
   gzip_min_length 1024;
   gzip_types text/plain text/css application/json application/javascript application/wasm image/svg+xml;

   location /api/ {
       proxy_pass http://127.0.0.1:3001$request_uri;
       proxy_http_version 1.1;
       proxy_set_header Host              $host;
       proxy_set_header X-Real-IP         $remote_addr;
       proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
       proxy_connect_timeout 10s;
       proxy_send_timeout    180s;
       proxy_read_timeout    180s;
   }

   location = /sw.js {
       add_header Cache-Control "no-cache, no-store, must-revalidate" always;
   }
   location = /registerSW.js {
       add_header Cache-Control "no-cache, no-store, must-revalidate" always;
   }
   location = /manifest.webmanifest {
       add_header Cache-Control "no-cache" always;
   }
   location = /index.html {
       add_header Cache-Control "no-cache, no-store, must-revalidate" always;
   }
   location ^~ /assets/ {
       add_header Cache-Control "public, max-age=31536000, immutable" always;
       try_files $uri =404;
   }
   location / {
       try_files $uri $uri/ /index.html;
   }
   ```

   （`^~` 必须保留：宝塔模板自带 `.js/.css` 正则 location，会抢走 `/assets/` 的匹配）
8. **验证**：`curl -sk -H 'Host: ai.ququan.net' https://127.0.0.1/api/health` + 浏览器端到端

## 附录 B：数据库相关（独立话题）

- 迭代一般**不需要**动数据库；表结构变更时先备份再改（备份走 `go-backend/data/`，含 MySQL / PG 两类 dump）
- PG 恢复前先 `CREATE EXTENSION IF NOT EXISTS vector;`（缺扩展会静默漏表）
- 数据库连接信息只存在于两份 `.env`（`DB_*` / `REDIS_*` 在 `go-backend/.env`，`PG_*` 在 `go-backend/agent/.env`）
