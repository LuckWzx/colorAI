# H5 改造实施方案

> 基于《移动端与App化评估》升级而来，聚焦「H5 阶段」的落地步骤。
> 日期：2026-09-08
> 本方案不包含 App/Capacitor 阶段内容（如 `baseURL` 改公网地址、后端 CORS）。

## 一、目标与范围

**目标**：把现有 Web 应用改造成手机浏览器体验良好的 H5，并具备 PWA 能力（可添加到主屏幕、离线可用）。

**范围（7 项任务）**：

| # | 任务 | 优先级 | 工作量 | 依赖 |
| --- | --- | --- | --- | --- |
| 1 | 图标资产准备 | P0 | 小 | 无 |
| 2 | PWA（manifest + Service Worker + theme-color） | P0 | 中 | 任务 1 |
| 3 | 刘海屏安全区适配 | P0 | 小 | 无 |
| 4 | 视口高度 `dvh` 修正 | P0 | 小 | 无 |
| 5 | 拖拽文案移动端化 | P1 | 小 | 无 |
| 6 | hover 依赖审计 | P1 | 中 | 无 |
| 7 | 补充站点导航 | P1 | 中 | 需产品确认 |

**非目标（不在本方案内）**：Capacitor 打包、原生能力、后端 CORS、`baseURL` 公网化、微信小程序。

## 二、分项实施方案

### 任务 1：图标资产准备

**现状**：`public/` 下只有 `favicon.svg`，无 PNG 图标，无法满足 PWA manifest 与 iOS 主屏幕图标要求。

**目标产物**：

```
public/
├── favicon.svg              # 已有，保留
├── apple-touch-icon.png      # 180×180（iOS 主屏幕）
└── icons/
    ├── icon-192.png         # 192×192
    ├── icon-512.png         # 512×512
    └── maskable-icon-512.png # 512×512，maskable（安卓自适应图标）
```

**做法（推荐）**：用官方工具从源图批量生成：

```bash
# 先准备一张 ≥512×512 的源图（可放大品牌 CMYK 四色标，或直接导出一张高清 PNG）
npx @vite-pwa/assets-generator --preset minimal-2023 源图.png
```

**做法（备选）**：手动用 Figma / 在线工具把 `favicon.svg` 导出为上述 4 个尺寸的 PNG，放到对应目录。

**验收**：`public/icons/` 与 `public/apple-touch-icon.png` 存在，尺寸正确。

### 任务 2：PWA（manifest + Service Worker + theme-color）

**现状**：`index.html` 无 `manifest`、无 `theme-color`、无 `apple-touch-icon`，`package.json` 无 PWA 相关依赖。

**步骤 2.1**：安装依赖

```bash
npm i -D vite-plugin-pwa
```

**步骤 2.2**：`vite.config.ts` 引入插件（在 `plugins` 数组内追加）

```ts
import { VitePWA } from 'vite-plugin-pwa'

VitePWA({
  registerType: 'autoUpdate',
  includeAssets: ['favicon.svg', 'apple-touch-icon.png'],
  manifest: {
    name: '曲泉AI - 专业色彩智能体',
    short_name: '曲泉AI',
    description: '色彩处理智能应用：校色、取色、色彩转换、色差对比',
    theme_color: '#0E4D64',      // brand-primary
    background_color: '#F4F5F3', // brand-paper
    display: 'standalone',
    start_url: '/',
    icons: [
      { src: '/icons/icon-192.png', sizes: '192x192', type: 'image/png' },
      { src: '/icons/icon-512.png', sizes: '512x512', type: 'image/png' },
      { src: '/icons/maskable-icon-512.png', sizes: '512x512', type: 'image/png', purpose: 'maskable' },
    ],
  },
  workbox: {
    // 关键：/api 请求不进缓存，始终走网络，避免接口数据被 SW 缓存成旧值
    navigateFallbackDenylist: [/^\/api\//],
    runtimeCaching: [
      {
        urlPattern: /^\/api\//,
        handler: 'NetworkOnly',
      },
    ],
  },
})
```

**步骤 2.3**：`index.html` 头部补充 meta

```html
<meta name="theme-color" content="#0E4D64" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<meta name="apple-mobile-web-app-capable" content="yes" />
<meta name="apple-mobile-web-app-status-bar-style" content="default" />
```

> `vite-plugin-pwa` 会自动注入 `<link rel="manifest">` 与 SW 注册脚本，无需手动改 `main.tsx`。

**验收**：
- `npm run build` 后 `dist/` 内有 `manifest.webmanifest`、`sw.js`、`registerSW.js`
- Chrome 移动端「添加到主屏幕」成功，图标、启动页、全屏模式正常
- 断网后刷新页面，静态资源仍可加载（`/api` 接口走网络、正确报错而非返回旧数据）

### 任务 3：刘海屏安全区适配

**现状**：viewport 无 `viewport-fit=cover`，固定导航和底部弹层未处理 `safe-area-inset`。

**步骤 3.1**：`index.html` 的 viewport 加 `viewport-fit=cover`

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover" />
```

**步骤 3.2**：`src/index.css` 增加安全区工具类

```css
@layer utilities {
  .pt-safe { padding-top: env(safe-area-inset-top); }
  .pb-safe { padding-bottom: env(safe-area-inset-bottom); }
  .px-safe { padding-left: env(safe-area-inset-left); padding-right: env(safe-area-inset-right); }
}
```

**步骤 3.3**：应用到固定元素

| 位置 | 文件 | 改法 |
| --- | --- | --- |
| 顶部固定导航 | `src/components/Navbar.tsx:56`（`fixed top-0` 的 `<nav>`） | 加 `pt-safe`，让内容区避开刘海 |
| 底部弹层（移动端 `items-end` 上滑面板） | `src/pages/PartnerCooperation.tsx:357`、`:642` | 内层卡片加 `pb-safe` |
| 底部弹层 | `src/pages/Wallet.tsx:714` | 内层卡片加 `pb-safe` |

> 说明：Navbar 本身 `bg-white/90`，加 `pt-safe` 后顶部安全区仍被导航背景覆盖，视觉连续。

**验收**：iPhone 刘海屏 + 底部横条机型下，顶部导航不被刘海遮挡、底部弹层不被横条遮挡。

### 任务 4：视口高度 `dvh` 修正

**现状**：项目用 Tailwind **3.4.17**，已内置 `h-dvh` / `min-h-dvh` 等工具类，**无需自定义 CSS**。

**替换清单**：

| 位置 | 现状 | 改为 |
| --- | --- | --- |
| `src/pages/Workspace.tsx:750` | `h-screen`（全屏工作台，问题最严重） | `h-dvh` |
| `src/components/Layout.tsx:15` | `minHeight: 'calc(100vh - 140px)'` | `minHeight: 'calc(100dvh - 140px)'` |
| `src/index.css:12` | `min-height: 100vh;`（body） | 加一行 `min-height: 100dvh;`（放其后作覆盖，`100vh` 留作旧浏览器回退） |
| 各页面 `min-h-screen`（约 18 处） | `min-h-screen` | `min-h-dvh`（风险低，可统一替换） |

> `h-screen` 是「定高 + overflow-hidden」，iOS Safari 地址栏展开时 `100vh` 会超出可视区导致底部被裁切；`h-dvh` 随动态视口变化。`min-h-screen` 只是最小高度，影响较小，属一致性优化。

**验收**：iOS Safari 下地址栏收起/展开，工作台底部输入区不被裁切；Android Chrome 无异常。

### 任务 6：hover 依赖审计

**现状**：全项目约 118 处 `hover:`，但揭示型（`opacity-0` → `group-hover:opacity-100`）仅 6 处，且全部是 `pointer-events-none` 的装饰性渐变（`ColorLibrary.tsx:523/532`、`Community.tsx:465`、`Home.tsx:189` 等），**触屏无功能风险**。其余为颜色 / 位移反馈。

**动作**：
1. 跑一遍确认无遗漏的功能性 hover 隐藏：
   ```bash
   grep -rn "opacity-0" src --include="*.tsx" | grep -i "group-hover"
   ```
2. 若发现「按钮/输入框默认 `opacity-0`、仅 hover 显示」的控件 → 改为常显，或改用 `active:` / 点击切换。
3. 装饰性 hover（颜色、`translate`、`scale`）保留，不影响触屏。

**验收**：触屏上不存在「看不见但可点」的控件；桌面端视觉不变。

### 任务 7：补充站点导航

**现状**：`Navbar.tsx` 桌面和移动端均无站点导航链接，汉堡菜单（`lg:hidden`）内目前只有登录按钮，站点导航完全依赖首页 CTA。

**需产品确认**：哪些入口进入主导航。建议候选：工作台（`/workspace`）、知识库（`/knowledge`）、色彩社区（`/community`）、品牌色库（`/color-library`）、趋势报告（`/trend-report`）。

**方案**：
- 桌面端：Logo 右侧加一行导航链接（`hidden lg:flex`）。
- 移动端：补齐汉堡菜单展开内容（当前 `mobileMenuOpen` 分支里只有登录按钮，补充上述导航链接列表）。
- 高亮当前路由（`useLocation().pathname` 匹配）。

**验收**：用户能从任意页面通过导航到达主要功能页；移动端汉堡菜单可正常展开/收起。

## 五、风险与注意

1. **Service Worker 缓存更新**：`registerType: 'autoUpdate'` 会在新版本部署后自动更新 SW，但用户需刷新/重开一次才生效；如遇「新版本未生效」，先排查 SW 是否命中 `/api` 缓存。
2. **`/api` 缓存隔离**：务必配置 `navigateFallbackDenylist` 与 `NetworkOnly`，否则接口数据会被缓存成旧值。
3. **图标源图**：`favicon.svg` 是 9px 小色块，直接放大会糊；建议重新画一张高清品牌标作源图。
4. **`min-h-dvh` 兼容性**：`dvh` 单位在 iOS 15.4+ / 现代浏览器支持；`index.css` 的 body 已用 `100vh` 做回退，其余用 Tailwind 的 `dvh` 类即可（Tailwind 自动不带回退，如需旧机兜底可保留原 `h-screen` 与 `h-dvh` 并用——旧浏览器忽略 `h-dvh`）。
